# OctoAcme Project Management Docs

A central entry point for OctoAcme's project management guidance.

## Project management processes

OctoAcme follows a customer-first, iterative lifecycle: initiate work by validating the business need, success measures, stakeholders, and go/no-go decision; plan approved work into prioritized increments with clear acceptance criteria, owners, estimates, dependencies, risks, and a Definition of Done; execute and track delivery through a project board, regular team and stakeholder updates, testing, reviews, and blocker escalation; release through readiness checks, deployment verification, and rollback planning; and close with a retrospective that turns lessons into tracked improvements.

Project Managers coordinate delivery, schedules, risks, and communication. Product Managers define outcomes, prioritize the backlog, and measure success. Developers build and test the work, QA validates acceptance criteria, and stakeholders provide input and approvals. Teams use standups, weekly delivery and PM/Product Manager syncs, monthly stakeholder updates, and demos to maintain alignment. Quality practices include automated tests and linting, appropriate unit and integration tests, smoke tests for critical flows, security scanning, manual QA when needed, and post-deployment checks.
